**前端等于策划原型，是整个项目的蓝图。功能设计框架不能改 —— 改了就不符合客户要求。**
我们做的是优化、完善、补充**服务端**。

**但假数据是例外：静态页面里写死的假数据不应该存在，必须删掉、换成真实数据。**
假数据本身就是「这个 API 根本没通」的证据。

**Why:** 2026-09-05 用户明确划的这条线。前端界面是产品既定设计，有哪些页面、
哪些功能、哪些入口、什么交互流程，都是客户认过的原型，动了就交付不了。
但硬编码的模拟数据不属于「设计」，它是半成品的痕迹 —— 界面看着有数据，
实际后端从没接上，这正是要修的东西。

**How to apply:**

| 类别 | 怎么处理 |
|---|---|
| 功能设计框架：页面、功能、入口、交互流程、布局 | **不动**。有意见先报告，由用户决定 |
| 写死的假数据 / mock / 兜底占位数据 | **必须删**，换成真实 API 数据；接不上就说明服务端缺东西，去补服务端 |
| 服务端问题：算错的数、没返回的字段、不生效的筛选、权限漏洞、并发缺陷 | 直接修 `api/` |
| 前端接线断了（设计没变，只是没工作） | 可以修，但在报告里点明动了哪个前端文件 |

「接线断了」的实例：字段名与服务端对不上（`active` vs `is_active`）、搜索框没绑
`onChange`、映射时漏字段导致某列永远为空、调用了根本不存在的函数、跨币种没折算。

**我犯过的错（2026-09-05）：** 把语言切换器从顶栏移除了 —— 那是删掉一个功能入口，
属于改动功能框架，已恢复。同期还有三处改了界面呈现而非修复缺陷：给修改密码弹窗
加输入框、把股东页的 ¥ 改成本位币符号、空下拉改成红色提示文案。这些都有技术理由，
但本该报告给用户拍板。

相关：[[scope-no-new-features]]（不扩展前端没有的功能）。三条边界合起来是：
不长新页面、不改既有设计、但要把假数据换成真数据。
